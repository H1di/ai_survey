## Часть 1 — Архитектура и качество кода

### 1.1 Карта реального потока данных ✅ (проверено живым прогоном)

```
Entry (entryChoice + dreamAnswer)
  → POST /api/session/start                    → session.step = "demographics"
Demographics (3 вопроса: sex, age, country)
  → POST /api/session/demographics ×3          → step = "depth_choice"
Depth choice (short=20 / deep=50)
  → POST /api/session/big-five-depth           → aiEngine.generateBigFiveItems
                                                  (AI → при ошибке/без ключа: IPIP-фоллбек) → step = "big_five"
Big Five (Likert 1–5)
  → POST /api/big-five/answer ×20/50           → computeBigFiveScores + deriveBigFiveTraits → step = "values"
Values (40 A/B)
  → POST /api/values/answer ×40                → computeValuesScores → step = "complete"
"Run Life Path Engine"
  → POST /api/direction/question               → generateDirectionQuestions (AI/фоллбек), 3 вопроса
  → POST /api/direction/answer ×3              → computeDirection (детерминированный tally) → proposedDirection
  → confirm | refine (×≤2) | choose            → direction; confirm тянет generateNarrowingQuestions
  → POST /api/professions/narrow ×2            → generateProfessions (ровно 3)
  → POST /api/professions/select               → selectedProfession
  → POST /api/roadmap/generate                 → generateRoadmap → roadmaps[professionId]
```

Все AI-вызовы идут через `buildProfileDigest` (`backend/prompts.js:12`) — дайджест включает демографию, OCEAN 0–100, производные черты и 8 values-оценок. Поток целостен, живой прогон прошёл от entry до roadmap без ошибок в консоли.

### 1.2 Согласованность контрактов backend ↔ frontend ✅

Проверено по всем эндпоинтам: `questionId/value` (демография), `itemId/value` (Big Five), `questionId/choice` (values) — совпадают в `backend/server.js`, `backend/questionEngine.js` и `frontend/src/api.js` + `App.jsx`. Значения `session.step` (`demographics/depth_choice/big_five/values/complete`) одинаковы на обеих сторонах. Расхождений не найдено.

- **Желательно** — контракт держится на ручной дисциплине: `VALUES_DIMENSIONS` продублирован в `frontend/src/components/ProfileCharts.jsx:32-41` (комментарий «Must match…»), `REFINE_REASONS` — в `frontend/src/App.jsx:247-252` против `backend/directions.js:202`. Дрейф никейс не поймает — вынести в shared-константы или e2e-тест соответствия.
- **Желательно** — `nextQuestion` и `valuesDimensions`, отправляемые в снапшотах (`backend/server.js:80-81`), фронтендом не читаются — мёртвый payload.

### 1.3 Дублирование логики между легаси и активным кодом — **важно**

`server/` (Express, 3 эндпоинта: `generate-paths`, `tradeoff-questions`, `expand-branch`) и `client/` (CRA, 15/38 статичных вопросов, AppContext, TradeoffModal) — это **полное параллельное приложение** старой модели данных. Дублируются даже имена компонентов (`GraphView/index.jsx`, `NodeComponent.jsx`, `BranchEdge.jsx` есть и в `client/`, и во `frontend/`), что регулярно путает поиск по проекту.

Хуже того, **корневой `CLAUDE.md` описывает только легаси** (порты CRA, `client/src/state/AppContext.js`, `/api/generate-paths`) — любой AI-агент, зашедший в репозиторий, начинает работать не с тем кодом. `README.md:79-85` тоже наполовину устарел (документирует удалённые `/api/session/premium` и `/api/questions/answer`). Свежие коммиты уже случайно цепляют легаси (`c0155b9` переименовал `client/src/pages/questions.js`).

### 1.4 Обработка ошибок — в целом сильная ✅, две дыры

Что хорошо (проверено кодом и живым прогоном):
- Нет ключа / упал OpenAI / невалидный JSON → каждый из 6 генераторов в `backend/aiEngine.js` имеет детерминированный фоллбек; нормализаторы (`aiEngine.js:212-322`) бросают на структурно неверных payload'ах, и вызов уходит в фоллбек. Поток «никогда не ломается» — подтверждаю.
- Сессия не найдена → 404 (`sessionStore.js:59-69`); некорректные ответы → 400 с внятными сообщениями и whitelist-валидацией (`questionEngine.js:78-121`).

Проблемы:
- **Важно** — *тихая деградация*: пользователь никак не узнаёт, что работает фоллбек. Живой прогон: в refine-карточке я написал «I want more hands-on creative work», UI показал «Thinking…» — но `fallbackRefineDirection` (`aiEngine.js:198-205`) полностью игнорирует текст и просто берёт следующий по счёту tally. Продукт делает вид, что «подумал». Прокинуть `hasOpenAIKey` (он уже есть в `/api/health`) в UI и показывать «offline-режим».
- **Важно** — нет таймаутов: `runJsonCompletion` (`aiEngine.js:324`) не задаёт timeout (у OpenAI SDK дефолт ~10 мин), `fetch` в `frontend/src/api.js:1-17` — без AbortController. Зависший вызов = зависший на минуты «Thinking…» без кнопки повтора.

### 1.5 Состояние сессий — **критично** (для любого деплоя)

`SessionStore` — `Map` в памяти (`backend/sessionStore.js:13-15`): **нет TTL, нет очистки, нет персистентности**.
- Рестарт сервера → все сессии в 404, а фронтенд даже не пытается восстановиться (см. 3.2 — reload и так убивает всё).
- Каждая брошенная сессия живёт вечно → неограниченный рост памяти; «Restart» на фронте (`App.jsx:770`) сервер не уведомляет.
- Горизонтальное масштабирование невозможно без sticky sessions.
Для локального MVP терпимо, для любого публичного запуска — блокер. Минимум: TTL-очистка по `updatedAt`; следующий шаг: Redis/SQLite.
- **Желательно** — `sendSessionSnapshot` шлёт полный стейт (все 40 values-вопросов + все Big Five items) на **каждый** из 63–93 ответов — десятки КБ на клик.

### 1.6 Фронтенд-стейт ✅ (активный код); рассинхрон — только в легаси

Активный `frontend/` вообще не имеет AppContext: единственный источник правды — серверный снапшот, применяемый целиком в `applySessionSnapshot` (`App.jsx:461-487`); локальны только view-индексы (`demoIndex`, `bigFiveIndex`, `valuesIndex`) и busy-флаги. Рассинхронизации не нашёл ни в коде, ни в прогоне. Упомянутый в задании конфликт «`AppContext` vs локальный `useState` графа» реально существует, но в легаси `client/` (`client/src/state/AppContext.js:8-9` держит `graphNodes/graphEdges`, а `client/src/pages/Graph.jsx:22-23` рендерит собственные `useState`) — уйдёт вместе с легаси.

### 1.7 Тесты — backend хорошо, frontend ноль — **важно**

- `backend/tests/` — 5 файлов, 39 тестов, все проходят через `npm test` (`node --test`). Покрыты: гарды и порядок роутов, refine/reject/choose-цикл, tally направлений, нормализаторы AI-payload'ов, сериализация сессии. Достойный уровень для MVP.
- Frontend-тестов нет вообще (ни unit, ни e2e). Самая хрупкая логика — `buildLifePathGraph` (`App.jsx:258-375`) и каскад dock-карточек (`App.jsx:860-1011`) — не покрыта.
- CI отсутствует (`.github/` нет) — тесты запускаются только вручную.
- Ручная инструкция Verification в плане (`docs/superpowers/plans/2026-05-21-new-question-architecture.md`, Task 11) — адекватная: проверка обоих режимов (с ключом и без) и spot-check дайджеста. Но она разовая; в README воспроизводимого чек-листа нет.

### 1.8 Безопасность — **важно** (критично при публичном деплое)

- **Rate limiting отсутствует полностью.** Цепочка `session/start` → 3×`demographics` → `big-five-depth` — это 1 OpenAI-вызов за ~5 дешёвых запросов, без капчи и лимитов; `direction/refine` даёт ещё до 2 AI-вызовов на сессию. Кошелёк можно осушить скриптом. (`backend/server.js` — ни одного лимитера.)
- **CORS открыт всем**: `app.use(cors())` (`server.js:36`) против легаси, где origin был ограничен. Вместе с отсутствием лимитов любой чужой сайт может гонять ваш API. Плюс сервер слушает `*:3001` (виден в LAN).
- **`dreamAnswer` не ограничен по длине** (`server.js:68-72`): до 1 МБ текста (лимит body-parser) попадает в **каждый** AI-промпт — усилитель расходов и вектор prompt-injection. Для сравнения: `country` ≤ 80, `feedbackText` ≤ 500 — забыли только dream.
- **`server/.env` лежит на диске** (легаси, май 2026) — если там боевой `OPENAI_API_KEY`, его надо ротировать и файл удалить. Гитигнорирован, в истории git его нет (проверено), но риск утечки с диска остаётся.
- Хорошее: ключ только через env ✓, `express.json({limit:"1mb"})` ✓, whitelist-валидация всех ответов ✓, Big Five items отдаются клиенту без `trait/reverse` (ключ скоринга не утекает, `sessionStore.js:187`) ✓.

Рекомендация: **удалить каталоги в отдельном коммите**, пометив точку тегом `archive/legacy-cra-2026-07` (история git всё сохраняет; отдельная ветка-архив не нужна). ## Часть 2 — Психологическая валидность методики

### 2.1 IPIP-фоллбек: IPIP-50 корректен ✅, Mini-IPIP-20 содержит ошибку ключа — **критично**

- `IPIP_50` (`backend/bigFiveItems.js:27-83`) сверен с публичными Goldberg IPIP Big-Five Factor Markers: формулировки, распределение (E 5+/5−, A 6+/4−, C 6+/4−, N 8+/2−, O 7+/3−) и reverse-ключи — точные. ✅
- `MINI_IPIP_20` — две ошибки против оригинала (Donnellan et al., 2006):
  1. **`mip_8` (`bigFiveItems.js:12`)**: «I have difficulty understanding abstract ideas» помечен `trait: "C", reverse: true`. Это **пункт Openness/Intellect** (в оригинале — O−). Сейчас человек, которому трудны абстракции, получает заниженную Conscientiousness, а O считается по 3 пунктам вместо 4. В «коротком» режиме (дефолтный выбор большинства) искажены сразу две шкалы из пяти.
  2. **`mip_15` (`bigFiveItems.js:19`)**: «I have excellent ideas» — пункта нет в Mini-IPIP (он из IPIP-50); на месте C-слота при этом отсутствует оригинальный «I like order». Итог: набор перестаёт быть валидированным Mini-IPIP, хотя код называет его так.
- Формула reverse-скоринга `6 − raw` и нормировка `((mean−1)/4)×100` (`questionEngine.js:129-153`) — корректны. ✅
- **Желательно** — якоря шкалы: IPIP валидировался на шкале точности («Very inaccurate … Very accurate»), в приложении — agree-шкала (`App.jsx:30-36`). Допустимая адаптация, но ещё один шаг от валидированного инструмента.

### 2.2 AI-генерация Big Five пунктов — методологически необоснованна — **важно**

Риск, названный в задании, подтверждаю и усиливаю: сгенерированные пункты не имеют психометрических свойств (не проверены факторная нагрузка, сложность, направленность), и **каждая сессия получает другой инструмент** — сравнимость результатов между пользователями и повторными прохождениями отсутствует. Технически валидация тоже дырявая (`aiEngine.js:485-502`): проверяется только общее число пунктов и допустимость `trait` — модель может вернуть 8 пунктов O и 1 пункт C, дубли `id` (коллизии в `bigFiveAnswers`), все пункты прямые (без reverse — усиливает acquiescence bias). Если какой-то черты нет вообще, `computeBigFiveScores` молча ставит 50 (`questionEngine.js:145-147`).

**Рекомендация:** сделать статичные IPIP-наборы дефолтом (они уже в репозитории и бесплатны), AI-генерацию либо убрать, либо спрятать за флаг «экспериментально» с жёсткой валидацией: ровно N/5 на черту, ~половина reverse, уникальные id, дедупликация формулировок.

### 2.3 40 A/B values-вопросов — систематические смещения — **важно**

- **Позиционное смещение + социальная желательность.** Балл начисляется только за выбор «A» (`questionEngine.js:198`), и «A» — всегда левый/первый вариант. Полюса не перемешаны ни разу за 40 вопросов. В `meaning_impact` все пять «A» — социально одобряемые («Help people directly», «Contribute to society», «Work that feels meaningful») против «прагматичных» B — вариант B почти не даёт различающей информации.
- **Демаскировка конструкта**: во время ответа показывается измерение с эмодзи («💰 Economic Return (1/5)», `App.jsx:194-198`) — усиливает подгонку ответов под желаемый образ.
- **Смысловые дубли внутри измерений** (`questionPool.js:78-127`): `economic_return` №2 «Stable income every month / Income that can grow but is uncertain» ≈ №5 «Guaranteed income / Performance-based income»; №3 ≈ №4 (security vs risky-reward); `achievement` №1 «Climb career ladder fast / Stay in stable role» ≈ №5 «Ambitious trajectory / Consistent progression». Дубли не добавляют информации, но удлиняют опрос.
- **Межразмерностные пересечения**: `lifestyle` №3 «Fixed hours, predictable routine / Flexible hours» почти совпадает с `independence` №4 «Control over schedule / Structured schedule», но полюса приписаны разным измерениям с противоположной ориентацией; «стабильность» размазана между `economic_return`, `structure` и `lifestyle` — измерения не ортогональны, интерпретация профиля «5/5 Structure при 5/5 Independence» противоречива.
- **Желательно** — бинарный форс-чойс, агрегируемый как нормативный балл 0–5, — грубая шкала; 4-балльная сила предпочтения дала бы больше дисперсии при той же длине.

### 2.4 `deriveBigFiveTraits` — формула корректна ✅, имена нестандартны

`behaviourTendencies = (A + C + (100−N))/3` — это Stability (α) по DeYoung; `decisionPriorities = (O + E)/2` — Plasticity (β) (`questionEngine.js:155-165`). Формулы соответствуют общепринятой модели Big Two. **Желательно**: назвать поля `stability`/`plasticity` (или задокументировать соответствие) и убрать произвол в порогах 65/35 в `describeTraits`.

### 2.5 Привязка к моделям профориентации — отсутствует — **важно** (для ценности продукта — критично)

- Ни Holland RIASEC, ни O*NET, ни ESCO нигде не используются: связка «Big Five + 8 ценностей → профессии» — целиком свободная интерпретация LLM. Пути звучат убедительно (промпты требуют «labor-market reality», `prompts.js:196`), но не опираются ни на какие данные о рынке труда — это тот самый риск «convincing but ungrounded», его стоит явно принять или закрыть.
- **Отдельная находка: алфавитное смещение в выборе направления.** Направление определяется tally по 3 вопросам (`directions.js:172-199`), а промпт требует ≥8 разных `directionId` на 12 опций (`prompts.js:111`) — поэтому расклад «1-1-1» (три разных направления) очень вероятен. При равенстве голосов побеждает **первое по каталогу**, каталог отсортирован по алфавиту. Живой прогон подтвердил: голоса social/trades/law → предложено «Law & Public Service» (раньше всех в алфавите). Комментарий в коде объясняет алфавитный порядок защитой от tech-bias, но в самом частом случае он превращается в «Agriculture-first»-bias. Нужен настоящий tie-break: 4-й уточняющий вопрос, взвешивание голосов профилем или выбор пользователя из топ-N.
- Дешёвое улучшение без смены архитектуры: O*NET Interest Profiler (RIASEC) — public domain, как и IPIP; маппинг 8 values-измерений + OCEAN на RIASEC-коды дал бы обоснованный шорт-лист направлений, а O*NET/ESCO — реальные данные по зарплатам/перспективам для roadmap.

### 2.6 Коммуникация неопределённости — отсутствует — **важно**

Профиль подаётся как факт: радар OCEAN с точными числами («OCEAN: O=38, C=63…»), направления «picked from these survey scores» (`ProfileCharts.jsx:146-149` — единственный намёк на provenance). Нет ни «предварительный профиль», ни диапазонов, ни указания, что 20 пунктов — это скрининг, а не диагностика. Рекомендация: бейдж «Preliminary profile», интервалы вместо точечных значений на радаре при `depth=short`, и явная фраза о том, что результат — ориентир для размышления.

## Часть 3 — UX и логика пользовательского пути

### 3.1 Полный путь пройден E2E ✅

Живой прогон (fallback-режим): entry → 3 демографии → depth → 20 Big Five → 40 values → «Run Life Path Engine» → 3 direction-вопроса → предложение → refine (с текстом) → повторное предложение → confirm → 2 narrowing → 3 профессии на графе → confirm-модалка с whyFit → roadmap из 6 шагов с каскадной анимацией → детали шага → панель профиля. Ошибок консоли нет, битых состояний не встречено. Скриншоты: `.playwright-mcp/audit-*.png`.

### 3.2 Длина и утомляемость — **критично** (в связке с потерей сессии)

- Полный путь: 3 + 20/50 + 40 + 3 + 2 = **68–98 вопросов**. Это много, но одностраничные карточки со single-click проходятся быстро (~8–15 мин short).
- **Критично: F5/закрытие вкладки = полная потеря всех ответов.** `sessionId` живёт только в `useState` (`App.jsx:406`), в localStorage не пишется, хотя `GET /api/session/:sessionId` для восстановления уже существует (`server.js:85`). Живой прогон: reload на этапе roadmap → выброшен на entry-экран. Пользователь, потерявший 60+ ответов на 70-м вопросе, не вернётся. Починка тривиальна: persist `sessionId` + рефетч снапшота на старте.
- **Важно**: нет сквозного прогресса — на старте values человек, уже ответивший на 23+ вопроса, видит деморализующее «0 / 40». Показать общий прогресс пути и честную оценку времени до конца (карточка Depth оценивает только Big Five-блок).
- **Желательно**: дубли в values (см. 2.3) субъективно ощущаются как «меня уже спрашивали» — чистка списка сократит опрос без потери информации.

### 3.3 Понятность графа ✅ с оговорками

Подписи ясные: «YOUR DIRECTION», «PROFESSION», нумерованные шаги роадмапа с таймфреймами; hint в шапке меняется по этапам («Direction locked — now narrow it down» → «Click a profession to continue»). Легенда не нужна — уровней всего три. Пункты задания про `BRANCH_THEMES`-легенду и «заблокированные» темы к активному приложению не относятся (см. преамбулу): `BRANCH_THEMES` — мёртвый экспорт (`questionPool.js:1-37`), UI-замка нет.
- **Важно (контент)**: в fallback-режиме roadmap — один шаблон на все профессии («Foundations → First real projects → …», `aiEngine.js:150-196`), а whyFit — одна дежурная фраза. В связке с «тихой деградацией» (1.4) пользователь получает генерик, поданный как персональный анализ.

### 3.4 Состояния загрузки ✅, но без таймаутов — **важно**

Лоадеры осмысленные и везде: «Generating items…» на depth-карточке, «Reading your answer…»/«Finding your professions…» в dock-карточках, «Building your roadmap…» в модалке, анимированный loading-узел на графе во время roadmap-генерации. «Зависшей кнопки» нет. Но при реальном AI-вызове (3–8 с) нет ни таймаута, ни ретрая (см. 1.4) — если OpenAI подвиснет, «Thinking…» бесконечен; сеть упала — только текст ошибки внизу без кнопки «повторить».

### 3.5 Мобильная адаптивность — базово ок — **желательно**

На 390×844: горизонтального переполнения нет (scrollWidth 378), A/B-пары и depth-карточки складываются в одну колонку (`App.css` @media 760px), reduced-motion уважается. Слабые места: шапка графа на мобильном ломается в неровную сетку (хинт-текст колонкой, логотип в две строки — скриншот `audit-mobile-graph.png`); панель профиля перекрывает весь экран без явного «вернуться к графу»; узлы графа мелковаты для тапа при отдалении.

### 3.6 Дисклеймер — отсутствует — **важно**

Ни на одном экране нет текста о том, что это ориентировочный инструмент, а не профессиональная консультация/психодиагностика. Для продукта, советующего смену карьеры на основе 20-пунктного скрининга, это и этическая, и юридическая гигиена. Добавить короткий дисклеймер на entry и в панель профиля + строку в confirm-модалке роадмапа.

## Решение по легаси `server/` / `client/`

**Удалить оба каталога из рабочего дерева** (отдельным коммитом, с тегом `archive/legacy-cra-2026-07` на пред-удаленческий коммит), предварительно удалив `server/.env` с диска и ротировав OpenAI-ключ, если он там боевой. История git полностью сохраняет код — отдельная архивная ветка избыточна. README-заглушка отвергнута: она не убирает дубли имён из поиска и не защищает от случайных правок (которые уже происходят — `c0155b9`, `4b5670f`). Одновременно переписать `CLAUDE.md` и секцию роутов `README.md` под актуальную архитектуру — это обязательная часть того же изменения, иначе агенты продолжат «чинить» несуществующее приложение.
