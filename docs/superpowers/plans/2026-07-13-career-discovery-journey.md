# Career Discovery Journey Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adapt the career-discovery spec to the v2 engine: one fixed static assessment (Big Five + RIASEC), a display-only "Career Discovery Journey" rail, a persona summary + per-axis takeaways in the profile panel, and a structured `whyThisFits` block generated by a separate second AI call on every output.

**Architecture:** Backend keeps the existing step machine minus `depth_choice` (demographics now advances straight to `big_five`; static banks are seeded/served without AI). Two new AI generators follow the repo's one-generator-per-artifact pattern (prompt builder in `prompts.js`, normalizer + deterministic fallback in `aiEngine.js`): `generatePersonaSummary` (runs at the `cv → tree` transition) and `generateWhyThisFits` (runs inside `/api/output/first|refine` after `buildScoredOutput`; the core output schema is untouched). Frontend renders everything from the session snapshot as before.

**Tech Stack:** Node + Express 5 (CommonJS), node:test; React 19 + Vite, Vitest.

**Spec:** `docs/superpowers/specs/2026-07-13-career-discovery-journey-design.md`
**Branch:** `feat/career-discovery-journey` (already created off `main`; spec committed as `90269f4`).

## Global Constraints

- Copy rules for every new user-facing string: plain human words; no jargon ("leverage/utilize/synergy"); no passive voice; short sentences, one idea each; every claim about the person names the specific answer/score behind it; no filler intros.
- The app must always work keyless: every AI generator needs a deterministic fallback, and the normalizer must throw on malformed payloads so the caller falls back.
- The server snapshot is the single source of truth; static question banks travel only on start / GET (resume) / riasec-start snapshots (`includeStatic`).
- Never serialize scoring keys: Big Five items go out without `trait`/`reverse`, RIASEC items without `type`.
- jobChar step is untouched: keep its 5|10 depth choice and AI tradeoff generation.
- The 7 `JOB_CHAR_PARAMS` ids and 10 Schwartz keys are cross-layer contracts — do not rename.
- Test commands: `cd backend && npm test` and `cd frontend && npm test -- --run`; frontend build: `cd frontend && npm run build`.
- Commit after every task. End commit messages with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

```js
// Interleave R,I,A,S,E,C so same-type items never sit in a block (less
// pattern-y for the respondent). Fixed instrument: 2 per type = 12 items.
function getStaticRiasecItems() {
  const byType = Object.fromEntries(
    TYPE_ORDER.map((t) => [t, RIASEC_POOL.filter((i) => i.type === t)])
  );
  const items = [];
  for (let round = 0; round < 2; round += 1) {
    for (const type of TYPE_ORDER) {
      items.push(byType[type][round]);
    }
  }
  return items.map((item, index) => ({ id: `ri_${index + 1}`, ...item }));
}

module.exports = { RIASEC_POOL, getStaticRiasecItems };
```

```js
    } catch (error) {
```

```js
      return fallbackWhyThisFits(session, output);
    }
  }
```

```js
// Maps the structured whyThisFits block to InfoPanel sections. Outputs
// generated before the block existed fall back to the legacy whyFit text.
export function whyThisFitsSections(output) {
  const why = output?.whyThisFits;
  if (!why) {
    return output?.whyFit ? [{ heading: "Why this fits you", text: output.whyFit }] : [];
  }
  const pts = (list) => (list || []).map((p) => p.point);
  return [
    { heading: "Why this fits — personality", items: pts(why.personality) },
    { heading: "Interests", items: pts(why.interests) },
    { heading: "Values", items: pts(why.values) },
    { heading: "Current skills", items: pts(why.currentSkills) },
    { heading: "Skills to develop", items: why.skillsToDevelop || [] },
  ].filter((section) => section.items.length);
}
```
