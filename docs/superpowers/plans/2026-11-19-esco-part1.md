# ESCO-first occupation content (Part 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every occupation fact the person sees (title, description, skills, education level) comes from ESCO; O*NET keeps only what ESCO lacks (RIASEC/work-values ranking, job zone, tech, US salary/outlook).

**Architecture:** A checked-in `backend/data/esco-snapshot.json`, built by a script from the official ESCO CSV package plus the official ESCO↔O*NET crosswalk. A pure `backend/engine/esco.js` answers "which ESCO occupations belong to this SOC" and assembles `output.esco`. Ranking stays on O*NET profiles, restricted to SOCs that have ESCO occupations; `buildOutput` puts the ESCO title/description/skills on top.

**Tech Stack:** Node + Express 5 (CommonJS, `node:test`), React 19 + Vitest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-19-esco-adaptive-path-design.md` (Part 1 + "Token budget"). Parts 2–4 get their own plans.

## Facts measured on 2026-11-19 (pin these)

- Crosswalk: `https://esco.ec.europa.eu/system/files/2023-08/ONET_%28Occupations%29_0_updated.csv` — "ESCO-O*NET Crosswalk", version 1 (Sep-22), O*NET-SOC 2019 × ESCO v1.1.0. 16 metadata lines, then header row `O*NET Id,O*NET Title,O*NET Description,ESCO or ISCO URI,ESCO or ISCO Title,ESCO or ISCO Description,Type of Match`. 4253 rows: broadMatch 2053, closeMatch 1432, exactMatch 498, narrowMatch 227, exactISCO 43 (ISCO-group URIs — ignored).
- Against `onet-snapshot.json`: 904 of 923 SOCs have ≥ 1 ESCO occupation; 2609 distinct ESCO occupations. The 19 SOCs without one drop out of ranking.
- ESCO has no Russian. Snapshot languages: `en, uk, fr, de, es, pt`; any other UI language reads `en`.
- ESCO **v1.2.1 classification, CSV** (not "delta", not "local api") is unpacked at `~/data/esco-v1.2.1/en/`, and the crosswalk is at `~/data/esco-v1.2.1/esco-onet-crosswalk.csv` (verified 2026-11-20). `occupations_en.csv` columns include `conceptUri, iscoGroup, preferredLabel, description, code`; `skills_en.csv` includes `conceptUri, skillType, reuseLevel, preferredLabel`; `occupationSkillRelations_en.csv` is `occupationUri, occupationLabel, relationType, skillType, skillUri, skillLabel`. Counts: 3043 occupations, 13 960 skills, 126 051 relations (67 600 essential / 58 451 optional); `reuseLevel` ∈ occupation-specific / sector-specific / cross-sector / transversal (5 blank → treat as transversal). Of the 2609 crosswalk URIs, 2 are absent from v1.2.1; 432 ESCO occupations have no crosswalk row (→ ISCO-group inheritance).
- Other languages (`uk, fr, de, es, pt`) are optional: the project owner downloads the same package type per language from `https://esco.ec.europa.eu/en/use-esco/download` (email form) and unpacks each to `~/data/esco-v1.2.1/<lang>/`. The build uses whichever language folders exist; `en` is required. Re-running the script later adds languages.

## Global Constraints

- Keyless mode must work end to end: the ESCO snapshot is local data; no ESCO network call at runtime.
- No new runtime or dev dependency (CSV parsing is hand-written).
- O*NET license blocks stay exactly as they are (`OnetAttribution`, `ONET_ATTRIBUTION` footnote).
- Salary/outlook stay visibly US-flagged.
- Sessions persisted before this change (outputs without `esco`) must still load, refine, accept and render. No `SESSION_SCHEMA_VERSION` bump.
- `frontend/src/motion/data/onet-field.json` is regenerated whenever the rankable SOC set changes, and carries no ESCO text.
- Precedence: where ESCO has a value, O*NET's value for the same thing is not shown.

## Review Focus

1. **Session saved before ESCO** — outputs have no `esco`; refine/accept/roadmap and the details panel behave exactly as today. Pinned in Task 4 (route test) and Task 6 (`escoSection({})` → null).
2. **AI returns an `escoId` that does not belong to the chosen SOC** (or none, or garbage) — the deterministic best match is used, never a foreign occupation. Pinned in Task 3 (`pickEsco`).
3. **UI language without ESCO coverage (`ru`)** — the English title shows, never `undefined`. Pinned in Task 3 (`escoTitle`).
4. **Crosswalk URI missing from the ESCO package** (renamed/deprecated between v1.1 and v1.2) — skipped and counted, build does not crash. Pinned in Task 2.
5. **Quoted CSV fields with commas, doubled quotes, newlines and a BOM** — parsed exactly. Pinned in Task 1.

### Task 2: ESCO snapshot build

**Files:**
- Create: `backend/scripts/build-esco-snapshot.js`, `backend/data/esco-snapshot.json`
- Test: `backend/tests/escoSnapshotBuild.test.js`

**Interfaces:**
- Consumes: `parseCsv` (Task 1); `onet-snapshot.json` SOC list.
- Produces: `transformEsco({ crosswalkRows, occupationsByLang, skillRows, relationRows, socs }) -> { snapshot, report }` and the file below.

Snapshot shape (exact):
```
{ version: "ESCO <package version> + ESCO-O*NET crosswalk v1 (Sep-22)", generated: ISO date,
  attribution: "This service uses the ESCO classification of the European Commission. Adapted: skill lists shortened, descriptions trimmed, some occupations linked to O*NET by ISCO group.",
  languages: ["en","uk","fr","de","es","pt"],
  skills: [[id, label, reuse]],            // id = UUID tail of the skill URI; reuse ∈ "o","s","c","t" (occupation-/sector-/cross-sector/transversal)
  occupations: [{ id, code, isco, titles: {en, uk?, fr?, de?, es?, pt?}, description,   // ≤ 300 chars, en
                  essential: [skillIndex], optional: [skillIndex],                     // ≤ 25 / ≤ 15, ordered o → s → c → t, then label
                  soc: [[soc, "exact"|"close"|"narrow"|"broad"]], inherited: bool }] }
```
`report` = `{ crosswalkRows, iscoRowsIgnored, urisMissingFromPackage, socsWithoutEsco, inheritedOccupations, droppedOccupations }`, printed by `main`.

Rules: crosswalk rows whose URI contains `/isco/` are ignored; `exactMatch→exact, closeMatch→close, narrowMatch→narrow, broadMatch→broad`; only SOCs present in `socs` are kept. An ESCO occupation with no crosswalk row inherits the SOC most frequent among crosswalked occupations with the same 4-digit `iscoGroup` (tie → lowest SOC string), with match `"broad"` and `inherited: true`; none in its group → dropped. Input files are read by header name; a missing column throws `Missing column <name> in <file>`.

### Task 3: `engine/esco.js` and the rankable SOC set

**Files:**
- Create: `backend/engine/esco.js`
- Modify: `backend/engine/onet.js` (`rankOccupations` filter; new export)
- Test: `backend/tests/esco.test.js`, `backend/tests/onet.test.js`

**Interfaces:**
- Produces:
  - `escoForSoc(soc) -> EscoOccupation[]` — sorted exact → close → narrow → broad, non-inherited first, then `titles.en`.
  - `pickEsco(soc, escoId?) -> EscoOccupation | null` — `escoId` among `escoForSoc(soc)` wins, else the first.
  - `escoTitle(occ, lang = "en") -> string` — `occ.titles[lang] || occ.titles.en`.
  - `educationLevel(isco: string, jobZone?: number) -> { eqfMin, eqfMax, source: "isco" | "isco+jobzone" }`.
  - `escoBlock(occ, { jobZone }) -> { id, uri, code, isco, title, titles, description, essentialSkills: string[], optionalSkills: string[], match, inherited, education, attribution }` (`uri = "http://data.europa.eu/esco/occupation/" + id`).
  - `hasEsco(soc) -> boolean`, `ESCO_ATTRIBUTION`, `ESCO_VERSION`, `ESCO_OCCUPATION_COUNT`.
  - From `onet.js`: `rankOccupations` returns only SOCs with `hasEsco`; new export `RANKABLE_OCCUPATION_COUNT`.

Education tables (exact). ISCO skill level by first digit of `isco`: `1→[3,4]`, `2→[4,4]`, `3→[3,3]`, `4..8→[2,2]`, `9→[1,1]`, `0→[1,4]`. Skill level → EQF: `1→[1,1]`, `2→[2,4]`, `3→[5,5]`, `4→[6,8]`; the ISCO range is the union over its skill levels. Job zone → EQF: `1→[1,2]`, `2→[3,3]`, `3→[4,5]`, `4→[6,6]`, `5→[7,8]`. With a job zone, the result is the intersection when non-empty (`source: "isco+jobzone"`), else the ISCO range alone (`source: "isco"`) — ESCO wins.
